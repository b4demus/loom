# Справочник Loom

[English](../README.md) · [Русский README](../README.ru.md)

## Сборка и запуск

```
.\build.ps1            # тесты + release WASAPI → dist\loom.exe
.\build.ps1 -Portable  # Windows x64 ZIP в dist\
dist\loom.exe          # или dist\loom.exe song.loom
```

Тулчейн — портативный `..\.tools\rust-daw` (windows-gnu + w64devkit), как у petal; путь можно
переопределить `LOOM_TOOLCHAIN`. В шелле: `. .\env.ps1`, дальше обычный `cargo`.
Для локальной сборки с ASIO запустите `.\build.ps1 -Asio`. ASIO собирается через CPAL 0.18.2. Для сборки нужны Steinberg ASIO SDK (`CPAL_ASIO_DIR`) и libclang
(`LIBCLANG_PATH`); `env.ps1` подхватывает портативные копии из `..\.tools\asio-sdk` и `..\.tools\libclang`.
Готовому `exe` эти инструменты не нужны. Локальные исправления сборки MinGW — в `vendor/asio-sys/LOOM_PATCHES.md`.
Рядом с `loom.exe` должен лежать `WebView2Loader.dll` (build.ps1 кладёт его в dist сам).
Каждый запуск — пустой проект (4 звука набора, один паттерн, пустой плейлист).
Флаги для проверок: `--audiotest [--wav=<файл>]` (аудиоклипы в плейлист, старт, уровень в лог), `--demo` (начать с демо-песни), `--song` (режим песни), `--play` (сразу старт),
`--plugtest [--inst=Имя] [--fx=Имя]` (скан, канал-плагин с нотами, эффект на мастер, старт; итог в
`%TEMP%\loom-dev.log`), `--log` (раскладка окон в тот же лог), `--keys` (диагностика клавиатуры). `loom.exe --scan <файл>` — дочерний режим скана.

Проверить плагин без приложения: `cargo run -p loom-host --example probe --release -- "<файл>" --run`.

## Устройство

- `engine/` — движок без UI и без звуковой карты:
  - `project.rs` — модель проекта (она же формат `.loom`, JSON). PPQ 96, шаг = 1/16.
  - `engine.rs` — транспорт, секвенсор с точностью до сэмпла, микс (громкость/пан/мьют/соло, мастер с мягким
    ограничителем). Проект приходит целиком; `Song::build` готовит его вне аудиопотока, `Engine::set_song`
    подменяет без аллокаций, каналы с тем же id сохраняют голоса.
  - `synth.rs` — синт «tone»: 2 осциллятора (PolyBLEP), SVF-фильтр с огибающей, ADSR, моно/глайд.
  - `sampler.rs` — сэмплер: высота по ноте, атака/затухание, one-shot, реверс, choke.
  - `kit.rs` — встроенный набор из 12 барабанов, синтезируется кодом при старте.
  - `decode.rs` — wav/aiff/flac/mp3/ogg через symphonia; `render.rs` — офлайн-сведение и запись wav 24 бит.
  - `tests/engine.rs` — попадание нот в долю, петля паттерна, режим песни, смена проекта на лету, экспорт.
  - микшер: канал → свой фейдер/пан → дорожка `mix` → слоты эффектов (dry/wet) → фейдер/пан дорожки →
    мастер (дорожка 0) → эффекты мастера → фейдер → мягкий ограничитель. Соло вставки глушит остальные вставки.
  - `plugin.rs` — плагин для движка: стерео-`Processor` с нотами (`MidiEv`) и `TimeInfo`. Процессоры лежат в
    таблице по id; старые возвращаются через «мусор» и освобождаются вне аудиопотока.
- `host/` — хост плагинов (Windows): VST3 через крейт `vst3` (привязки к SDK, MIT), VST2 — свои
  определения ABI (`AEffect`, опкоды; SDK VST2 Steinberg больше не лицензирует, его код не используется).
  Экземпляр живёт на UI-потоке, процессор — на аудио. Окна редакторов — Win32 (`window.rs`) с тёмным
  заголовком, владелец — окно loom. Состояние: VST3 — компонент+контроллер, VST2 — chunk или параметры.
  32-битные плагины не грузятся (64-битный процесс) — скан так и пишет.
- `app/` — Tauri 2: окно без рамки, вывод звука через cpal (WASAPI) в отдельном потоке, команды для UI
  (проект, транспорт, статус, файлы/диалоги, браузер `list_dir`/`preview`, плагины `plugin_*`). Скан плагинов —
  в дочерних процессах (`--scan`, по 4 за раз, таймаут 60 с) с кэшем `%APPDATA%\dev.b4demus.loom\plugins.json`.
  При смене звуковой карты плагины перенастраиваются на новую частоту. Экспорт WAV делает временные копии
  плагинов с их текущим состоянием.
- `ui/` — ванильный HTML/CSS/JS на токенах Glyph (JetBrains Mono, #141414, глина #BB7463, ASCII-поле).
  UI владеет проектом: каждая правка → `changed()` → перерисовка и отправка проекта в движок раз в кадр.
  - `core.js` — состояние, undo/redo, мост к Rust (в браузере без Tauri — заглушка), демо-песня.
  - `widgets.js` — плавающие окна, крутилки, меню; `rack.js`, `roll.js`, `playlist.js`, `panels.js` (канал, настройки).

## Управление

Разделение на стемы: меню `≡` аудиоклипа → «разделить на стемы…». Выбор вокала,
ударных, баса и остальных инструментов. HTDemucs работает локально на CPU, в отдельном
процессе с пониженным приоритетом; видеокарта и Python не нужны. Сеть исполняется через
ONNX Runtime CPU с ограничением числа потоков, без Burn NdArray. В первый раз скачивается
модель 316 МБ с проверкой SHA-256 и один раз сохраняется оптимизированный для CPU граф;
повторные запуски используют этот граф. Затем работает офлайн. Исходный файл обрабатывается целиком
(до лимита аудиодвижка 10 минут); длина, позиция, обрезка, скорость, питч, реверс и фейды клипа
сохраняются у стемов. Результат — отдельные WAV в `stems` рядом с проектом (без сохранённого
проекта — `Документы\loom\stems`) и отдельные дорожки плейлиста. По умолчанию оригинальный
клип остаётся заглушённым; весь импорт отменяется одним Ctrl+Z. Отмена обработки удаляет
незавершённые WAV. Если во время обработки открыт другой проект, WAV остаются на диске,
в новый проект они автоматически не добавляются. Рядом с `loom.exe` нужны `loom-stems.exe`,
`onnxruntime.dll` и `onnxruntime_providers_shared.dll`; build.ps1 копирует их автоматически.
Для сборки официальный CPU runtime подготавливает `tools/setup-onnxruntime.ps1`
(либо задайте `LOOM_ORT_DIR`). На Windows используется системный Visual C++ 2015–2022 x64 runtime.
На CPU длинные файлы обрабатываются значительно дольше коротких; есть прогресс и отмена.

Проверка без экрана и аудиоустройства: `python tools/stems-smoke.py --worker target/release/loom-stems.exe --cache <папка моделей>`.
Проверка отмены с тем же обработчиком, что использует интерфейс:
`dist\loom.exe --stemtest <входной WAV> <папка результатов> <папка моделей> --cancel`.

После изменения устройств в панели ASIO4ALL — «обновить входы» в том же меню. Полное имя выбранного входа видно справа и при наведении на `IN`. | Ctrl+S · Ctrl+Shift+S · Ctrl+O · Ctrl+N | файлы |

| Окна | `_` — свернуть в заголовок (ещё раз или двойной клик — развернуть), `□` — на весь стол / вернуть, `x` — закрыть |

| Аудиоканалы | у каждого звука аудиоклипов свой канал в стойке (волна вместо шагов, тот же звук — тот же канал): громкость, пан, мьют/соло и номер дорожки микшера канала действуют на все его клипы; бросить на канал другой звук — заменить во всех клипах; удалить канал — уйдут и клипы |
| Плейлист | клик — вставить текущий паттерн, тяните — двигать, края — длина/обрезка, Alt — без сетки, ПКМ — убрать, двойной — открыть паттерн. ЛКМ по линейке — точка старта: стоп возвращает к ней, следующий пуск начинает оттуда. Область петли выделяется и её края меняются только ПКМ+перетаскиванием или Shift+ЛКМ+перетаскиванием по линейке; обычный ЛКМ петлю не меняет. `L` или «↻ петля» — вкл/выкл, ПКМ без перетаскивания — меню петли. Петля сохраняется в проекте, экспорт WAV всегда охватывает всю песню |
| Навигация плейлиста | средняя кнопка + тяните в любом направлении; либо включите «✥ рука» и тяните левой. Внизу и справа — полосы прокрутки, Shift+колесо — по времени, Ctrl+колесо — масштаб. Ручная прокрутка отключает «→ следить», чтобы курсор не возвращал вид; кнопку можно включить снова. Home/End — начало/конец песни |
| ASIO4ALL | настройки (`*`) → `ASIO · ASIO4ALL v2`; входы микшера и запись используют тот же драйвер. «Панель ASIO…» открывает его настройки; после изменения доступных входов/выходов выберите драйвер повторно. Выбор устройства сохраняется между запусками; при ошибке переключения восстанавливается предыдущее устройство |
| Стойка | клик/протяжка по шагам, ПКМ — стереть, двойной клик по имени — настройки канала, ПКМ по имени — меню |
| Колесо | прокрутка; Shift — по горизонтали; Ctrl — масштаб; Alt — высота строк |

Аудиофайлы можно бросить на окно — появится канал-сэмплер; `.loom` — откроется проект.

Проверки интерфейса: `node --test tools/recording.test.cjs tools/playlist.test.cjs tools/mixer.test.cjs` — запись, именованные входы, маркер старта, жесты навигации и петля без устройства;
`cargo test -p loom -p loom-host --release` — выбор входов, отдельные WAV, открытие файлов без перезаписи дублей и однократная обработка Alt+R.
`dist\loom.exe --rectest --recaudio --track --multitrack --count` — сквозная проверка на текущем входном
устройстве (моно вставка 1 + стерео вставка 2, отсчёт, клипы и маршрутизация); результат в `%TEMP%\loom-dev.log`.
`cargo test -p loom --features asio --release asio4all_input_output_and_driver_switch -- --ignored --nocapture` —
проверка установленного ASIO4ALL: выход, два WAV со входов и возврат к WASAPI.

## Превью интерфейса без Rust

Из корня проекта запустите `python -m http.server 5190 --bind 127.0.0.1 --directory ui` и откройте `http://127.0.0.1:5190`. `?demo` — демо-песня, `?timer` — тикать по таймеру
(в скрытой панели браузера кадры анимации не приходят).
